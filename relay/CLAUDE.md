# Relay (`relay/src/`)

Deep reference for the relay. Root `CLAUDE.md` holds the repo-wide gotchas,
commands, and conventions — this file loads only when working under `relay/`.

v3 protocol: single-frame `hello` auth, epochs, account-derived routing, streams. The v2 register/challenge stack is gone.

- `server.ts` — WS listener: first text frame MUST be a signed `hello` (anything else → `PROTOCOL_VIOLATION` + close 1008; 10s hello-or-die timer). Verification order is fixed (do not reorder): Zod parse → clock window (`clockSkewMs`; fail = `AUTH_FAILED` with `serverTime` so clients self-heal, retryable) → Ed25519 sig over `buildHelloSigBody` (antgrid-wire; `relayHost` = normalized upgrade `Host` header captured at upgrade) → replay cache → license → epoch arbitration → `welcome`. The replay-cache record lands AFTER the sig verifies, so an unauthenticated hello flood can't consume cache capacity and evict a victim's cached nonce (a sig-invalid hello never needed replay protection). Config enforces `replayTtlMs ≥ 2·clockSkewMs` at load. Also serves `POST /internal/{revoke,expire}` for web push.
- **Error contract is law:** every relay error frame carries required `retryable`; only auth/protocol failures close the socket — stream and routing errors leave it open.
- `connections.ts` — live connections only (entry exists iff socket open and past hello; no tombstones, no retention states). Epoch arbitration per deviceId: higher OR EQUAL epoch supersedes (loser gets `SUPERSEDED`, its streams release before the winner inserts), lower rejected, pubkey mismatch vs the live holder rejected. Equal-epoch admission is load-bearing, not a tie-break nicety: epoch is per-process, so an equal-epoch hello is the same instance redialing onto its own half-open zombie — rejecting it strands the device because `SUPERSEDED` is `retryable:false` and clients stop reconnecting on it. It is paired with a freshness guard that runs BEFORE arbitration — a hello older than the live holder's admitting frame (`helloTs`), or repeating its `helloNonce`, is `AUTH_FAILED`. Both timestamps come from the same client clock so skew cancels; the nonce half covers only the same-millisecond case, so do not drop either. Do not drop the pair as redundant with the replay cache either: that cache is capacity-bounded, its records land before the license gate (so unlicensed hellos can evict them), and it is empty after a restart — without the guard, equal-epoch admission turns any such miss into a captured frame evicting a live device for good. An AGENT's deviceId is its account `deviceUuid` (`verify` binds them); an APP's is a per-machine slot, `<accountDeviceUuid>#<machineDeviceUuid>` — `verifyAppToken` deliberately does not bind, which is what lets one app hold a socket per machine without superseding itself. Never assume `hello.deviceId` is an account device id — anything driven by one (revocation) goes through `getByAccountDevice`, which collects the bare holder AND every slot scoped under it. **No cascade close**: on agent disconnect, its same-account app peers get `peer-offline` and their sockets stay open.
- `replay-cache.ts` — `(deviceId, nonce)` TTL cache (`replayTtlMs`, capacity-bounded) backing hello replay rejection.
- `license/` — gate enforced at agent `hello`; apps present their account token too (required — `verifyAppToken` → `{uid}`; the tokenless legacy-QR path is gone). `jwks-cache.ts` caches JWKS 24h (single-flight); an unknown-`kid` miss force-refreshes to self-heal seed rotation, but those refreshes are throttled (`kidMissRefreshCooldownMs`, 60s) so a self-signed hello cycling novel kids can't amplify into a per-request web fetch. Tokens are Better-Auth OAuth `client_credentials` access tokens, which carry **no `sub`/`jti`** — device identity is in the custom `deviceUuid` claim and the per-credential id in `azp`. `verify.ts` does Ed25519 verify (alg pinned `EdDSA`, issuer pinned to `deviceTokenIssuer(licenseIssuerUrl)` — `licenseIssuerUrl` is web's PUBLIC origin (defaults to `BETTER_AUTH_URL`), a DISTINCT config key from `licenseApiUrl` (which the relay uses only to fetch JWKS and may be an internal address) — mirrors web's `jwt-bearer.ts`; keep in lockstep); it maps `deviceUuid`→`claims.deviceUuid` and `azp`→`claims.jti` (the revocation discriminator; `azp` is stable across token re-mints, rotating only on device re-provision); `pk` claim = device pubkey. The relay reads no entitlement claim — `sessionLimit` is gone and tokens no longer carry it; relay license checks are purely identity/validity. `gate.ts`: verify → `claims.deviceUuid === hello.deviceId` (bare id; no `.projectId` split) → compare `claims.pk` to presented pubkey locally (no HTTP callback) → `cache.ts` (deviceId-keyed, capacity-bounded, `exp` enforced per-verify, revoked flagged in place). Verdict failures close 1008 with `LICENSE_INVALID|LICENSE_EXPIRED|LICENSE_REVOKED` (retryable:false); JWKS/network failure is `LICENSE_UNAVAILABLE` (retryable:true) — infrastructure, not a verdict. `/internal/revoke` takes the bare ACCOUNT device id **plus the revoking `userId`** and closes every socket `getByAccountDevice` finds *for that account* — an app holds one per machine, so a `getByDeviceId` lookup would leave a revoked phone routing, while dropping the account scope evicts a second account that legitimately holds the same deviceId (the device row is unique on `[userId, deviceId]`, so one phone image signed into two accounts yields two rows; their app SLOTS differ, so both are live at once). Same scope on `LicenseCache.markRevoked`, whose entries are deviceId-keyed and therefore shared by those two accounts. `userId` is optional on the wire for deploy skew only; absent, the revoke falls back to unscoped. Push endpoints (`/internal/revoke`, `/internal/expire`) close every live socket for the affected account device/user with code 4002 (`LICENSE_REVOKED`/`LICENSE_EXPIRED`); the ordinary disconnect fan-out (`peer-offline`) then notifies same-account peers — no separate revocation frame needed.
- `authz.ts` — `mayRoute(sender, target)` is the ONLY routing authorization: both sides proved account identity at hello, so routing reduces to same-account (`sender.claims.uid === target.claims.uid`). A denied target and an offline target get the identical `PEER_OFFLINE` (retryable) — an unauthorized sender must never be able to distinguish denial from absence (no presence oracle).
- Streams — `stream-open` (agents only) is **unmetered but not unbounded**, and the two are different invariants. Unmetered: the paid axis is a worker (agent-device) cap enforced by web at device registration (`checkCapAndUpsert` in `web/src/models/device.ts`; web/CLAUDE.md, the security-invariants paragraph), so the relay bills nothing per stream — metering open streams taxes the fleet view and warm-project LRU, and a cap checked at `stream-open` strands a machine mid-work. `SESSION_LIMIT_EXCEEDED` is retired but RESERVED in antgrid-wire's `ErrorCode` (`packages/antgrid-wire/src/relay-protocol.ts`): the relay never emits it, but bridge and app still decode it from relays predating the worker cap, so the name must never be reused for a new meaning. Bounded: `maxStreamsPerConnection` (default 1024) is a STRUCTURAL ceiling per connection, not a quota — ids are client-chosen and nothing expires them until the socket dies, so without it an agent grows the set until the relay is out of memory. Real machines hold single digits, so a client that hits it is broken or hostile → `STREAM_LIMIT_EXCEEDED`, `retryable:false`, socket stays open. Re-opening an id already held is exempt (it cannot grow the set, and the mux re-opens every attached stream on each `welcome`). Admission stays await-free (single-threaded TOCTOU discipline) — any future check must keep that. The relay never parses streamIds out of routed frames — the `{s, m}` envelope is sealed.
- `rate-limiter.ts` — per-IP connection limits + token-bucket on routed binary frames AND JSON text messages (`MESSAGE_RATE_LIMITED`, retryable; **the frame is DROPPED and only the sender is told**, so the peer waiting on a reply learns nothing — see below). Routed frames are keyed per **(pair, channel)**, not per pair: `pairKey` sorts, so one bucket per pair is shared by both directions and every channel, and a preview page load (dozens of subresources) then starves the control plane. Push delivery keeps its own budget (`MessageRateLimiter`, `RATE_LIMIT_PUSH_PER_SEC`) precisely so widening the preview budget never widens a third-party fan-out control.
- **A dropped routed frame is unrecoverable at the relay and only partly recoverable above it.** `RouteHeader` carries no message id and the error frame's `ref` is already claimed by stream-id dispatch, so neither end can learn *which* frame died. Recovery is therefore end-to-end and approximate: the app re-sends idempotent preview requests under the ORIGINAL `requestId` after a short grace, and the bridge's `TunnelManager` outbox replays the response it already produced rather than re-running the upstream fetch. Adding a message id to the route header is the only thing that would make this precise — until then, never assume a `MESSAGE_RATE_LIMITED` can be correlated to a request.
- Client-IP resolution (`antgrid-wire`'s `client-ip.ts`, shared with web) — behind a reverse proxy every peer is the proxy's address, collapsing the per-IP connection limit into one shared bucket; set `TRUSTED_PROXY_IPS` (comma-separated IPs/CIDRs) so the relay recovers the client from `X-Forwarded-For` (walked right-to-left past trusted hops — the spoof-safe direction; EVERY return is canonicalized, fallbacks included, so one address is one bucket key no matter which path produced it; `ip:port` and `[v6]:port` hop forms accepted, but an unbracketed `v6:port` hop is indistinguishable from a legal address and parses as one). Config parses `TRUSTED_PROXY_IPS` into `Cidr[]` at load via antgrid-wire's `parseTrustedProxies` (web's env loader uses the same one, so the two services cannot drift on syntax or shape), so nothing re-parses strings later; matching re-expands a v4 peer to mapped form, or an IPv6 range like `::/0` would validate and then trust nothing. Unset = header ignored; a directly exposed relay must never honour it. Any fallback taken while a forwarded header WAS present is warned (throttled per kind) — the untrusted-peer case is the likely misconfiguration and silent degradation is what makes it a support ticket. Keep the trust set as narrow as possible — every HOST inside a trusted range can forge its own reported client IP, so a whole subnet is acceptable only when all its containers are first-party. The proxy must also preserve `Host` (Caddy default) or hello signatures fail — `relayHost` binds the upgrade Host header, not a forwarded one. Deliberately hand-rolled: Bun 1.3.14's `node:net` BlockList panics the process on mapped-IPv4 cross-family checks (see file header).

**Security invariant:** no agent admission without a verified license JWT bound to the hello pubkey (sig + license gate; the cache never marks an entry valid until both verify and pubkey-bind complete); apps authenticate with their own account token. The gate answers *is this device who it says it is and still entitled to connect* — nothing past hello re-checks entitlement, so no verb may be made to depend on a quota the relay does not hold. Routing is account-derived only (`mayRoute`, checked fresh on every routed frame) — no vouching step, no per-peer grant to revoke — and an agent disconnect immediately severs routing (`peer-offline`) without closing the app's socket.
