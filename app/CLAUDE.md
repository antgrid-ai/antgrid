# App (`app/lib/`)

Deep reference for the Flutter app, including the **Design Rules** at the bottom
— this file loads only when working under `app/`, and all Flutter UI lives here.
Root `CLAUDE.md` keeps the repo-wide gotchas, commands and conventions. The
app's relay layer lives outside this tree: see
`packages/antgrid_relay_client/CLAUDE.md`.

What may be written in any `CLAUDE.md`, this one included, is governed by
*Maintaining these files* in the root `CLAUDE.md`.

## Component map

What each area owns, plus the contracts that span more than one of them.

- `providers/` — Riverpod providers (connection, terminal, file tree). `relay_connection.dart`: `RelayConnectionManager` holds ONE `RelayConnection` (one socket + one `MachineSession`) per bare machine `deviceUuid` — keys are normalized via `baseDeviceUuid`, so a compound `<uuid>.<projectId>` id lands on its machine's slot. `relayEpochProvider` = per-launch epoch (`antgrid.relay_epoch`, `dev.`-prefixed in a local dev build — see `storage_scope.dart` — in `SharedPreferencesAsync` — the legacy `SharedPreferences.getInstance()` API is not backed by the test platform mock; don't reintroduce it), `max(stored+1, unixSeconds)`.
- `connection/` — `ConnectionSupervisor`: level-triggered policy for ONE machine, re-deriving the whole ladder (`ConnRung.wanted → coords → socket → routable → established`) on every `evaluate()` rather than reacting to individual events, so a missed edge costs one late evaluation, not a dead connection. `SupervisorStatus` is `Climbing`/`Connected`/`Blocked(reason)`/`Released`; `Blocked` is sticky until a typed unblock input clears it. Per-rung equal-jitter backoff (`_backoffMs`: `min(base << attempt, cap)`, half always waited so jitter=0 never storms). `ConnMechanisms` (implemented by `relay_mechanisms.dart` for production) is the HOW — `resolveCoords`/`mintToken`/`dial`/`establishSession`/`release` — each a single no-retry attempt; the supervisor is the only WHETHER. `RelayConnection.statusStream` (in `providers/relay_connection.dart`) republishes the supervisor's status from construction; `providers/supervisor_status.dart`'s `supervisorStatusProvider` is the UI's single source of truth for REMOTE-machine connection state; the LOCAL bridge host's lifecycle (crash supervision, restart phases) surfaces separately via `providers/host_status.dart`'s `hostStatusProvider` (backed by `HostController.statusStream`).
- `providers/eager_control_planes.dart` — mobile-only proactive dials: at launch and resume, `AppShell` kicks the control planes of the most recently connected machines (capped, `kEagerControlPlaneCap`) via `kickEagerControlPlaneDials` in `control_plane.dart`, and the eager targets are unioned into the reaper's alive set so the sockets survive. Desktop stays fully lazy (an earlier eager-connect-everywhere design caused connection storms).
- `providers/recent_sessions.dart` + `providers/project_work_status.dart` — the live work-status maps, both filled imperatively by the app_shell control-plane reaper (single-writer; a per-machine `ref.watch` fan-in reproduced Riverpod's "rebuilt multiple times in the same frame" crash). `remoteSessionStatusProvider` is per SESSION and authoritative — the dot belongs to the session row, so an EXPANDED drawer project row carries none (a rollup beside the session rows only restated the loudest of them). The three project-level surfaces are the collapsed MACHINE band's aggregate (`machineWorkStatusProvider`, call-to-action states only), a COLLAPSED project row's aggregate (`projectWorkStatusProvider`, same narrow set — its sessions are off screen, so nothing else can carry the call to action), and the title bar's focused-project pill. An entryId absent from it (older bridge, cold project) is what makes a row fall back to `remoteProjectStatusProvider`, so never default it to an empty map. Only `remoteProjectStatusProvider` is seeded from the persisted cache, and that seed reaches ONLY the three project-level surfaces — with no per-session entry `sessionRowStatus` masks on `running`, which the cache loads false, so no row shows a cold-boot dot. A per-session entry also outranks the row's `running` flag (`sessionRowStatus`): the bridge files a status only for sessions it lists as running, while `running` comes from the cache, which loads false for every session — masking on it blanked the whole Recent list after a restart. **Retire the two maps together** — a closed socket or a dead host must clear BOTH (see the reaper's `_syncLabelSubscriptions` / `_pollLocalProjectStatus`): the per-session map wins in `sessionRowStatus`, so a stale entry surviving its socket is a dot nothing can clear.
- `providers/agent_catalog.dart` — `agentCatalogProvider`, registry key → `AgentDescriptor`, merged from every machine's `agent:tools.agents[]` advert over a persisted map. **The bridge is authoritative for what an agent is called and what it can do; the app only caches what it was told**, so a newly-registered agent needs no app release and the app ships no mirror of the bridge registry to drift. That rule, why cross-machine merging is sound, why an ABSENT key must render as unknown rather than `false`, and why an empty advert is a no-op are all on the declarations; `test/agent_catalog_test.dart` pins them. Three things reach past this file: a session already RUNNING in chat mode outranks the catalog (`session_mode_control.dart`) — the mode on screen cannot be reported impossible; the brand-mark map (`design/ab_agent_marks.dart`) stays app-owned because it is an ASSET with a designed monogram fallback, and `AbIcon` renders raw SVG, which is not something to accept off the wire; and **Handler coverage has two sources that never substitute for each other** — `handlerObservableFromCatalog` is the PRE-arm answer about an AGENT, while `HandlerSessionState.observability` off `handler:status` is the post-arm answer about a SESSION and outranks it wherever both are known. Null on either side means "nobody said"; `escalateOnly` must stay visibly distinct from `unsupported`.
- `providers/cached_sessions.dart` — the read-through session cache behind every non-focused drawer row and the whole Recent list. Two rules keep a mutation from being silently dropped: a change signal routed through a `StreamProvider` must carry a monotonic seq (`CacheChange`), since `AsyncData(x) == AsyncData(x)` notifies nobody and the same project changing twice in a row is the norm (same hazard, same fix as `relayConnectionChangesProvider`); and `cachedSessionsProvider` subscribes to `CachedSessionsStore.changes` DIRECTLY, so a drawer row's freshness never depends on something else keeping `cacheChangesProvider` alive. A local project only write-throughs while it is WARM — a session started (or deleted) from mobile in a cold local project still won't appear until it's opened.
- `providers/session_setup.dart` — per-session `worktree.setup` state, behind the workspace banner (`widgets/session_setup_banner.dart`) and the isolation badge's `preparing` arm. **Setup state is runtime-only bridge state and is never cached**: `CachedSessionsStore` strips `setup` on write and clears it on load, beside `running`/`deleting`, because a cache written mid-run restores `state: "running"` with nothing alive to finish it — a row that is permanently preparing. Read it through `sessionSetupProvider`, which projects `freshSessionsStateProvider` alone, and never off a `SessionEntry` that may have come from the cache; the honest cost is that only the FOCUSED project's rows can report setup at all. `sessionSetupPhase` is the single decode site for the bridge's state vocabulary and degrades an unrecognized one the way `sessionCheckoutHealth` does. `setup` is deliberately NOT a `checkoutState` value — that field answers "is this workspace usable" and a checkout is `ready` throughout the run, which is what makes Skip meaningful. The transcript is reached with `setup.terminalId` VERBATIM (`<checkoutId>:setup`): it resolves through the bridge's identity mapping and the bare name `setup` does not.
- `services/` — 7 per-project services (`FileService`, `SessionsService`, `TerminalService`, `ConfigService`, `SearchService`, `CommandService`, `PreviewService`), each `XxxService.fromSession(session)` owned by a `ProjectSession`. They subscribe to `session.heavyStream`/`statusStream` in their constructor (so welcome-cached messages are caught), send via `session.send(...)`, and have no app-wide singleton — `xServiceProvider` returns the focused project's instance. Local and relay flows are unified: `selectedProjectIdProvider` is the single focus id; `agentTransportForProvider(id)` picks relay vs local; `projectSessionProvider(id)` wires the session + 7 services. `PreviewService` assembles `tunnel:http-start`/`-chunk`/`-end` into a `Stream<List<int>>` the proxy hands to shelf; a request is retryable only while it has no head.
- `project/project_session.dart` — per-project aggregate (transport + MessageRouter + ProjectStatusNotifier + services). Lifetime via `ProjectSessionRegistry`, **no `autoDispose`**.
- `project/project_session_registry.dart` — warm-projects LRU with per-bucket caps (`warmCapForBucket` in `limits.dart`): desktop = local `kWarmCapLocal=10` + relay `kWarmCapRelay=30` as SEPARATE quotas (no shared budget — opening a relay socket never evicts a local agent), mobile = `kWarmCapMobile=3` for both. `touch(id, {required isLocal})` buckets each project; eviction stays within the overflowing bucket (oldest by last-focus time, `selectEvictionVictim` in `lru_policy.dart`; the just-focused project is protected). `onEvict` writes final status to cache and invalidates session+transport providers. v3: evicting a relay project closes its stream binding, not a socket — the machine's `RelayConnection` is released only when nothing on that machine needs it (control-plane reaper in `control_plane.dart`).
- `screens/` — terminal, file explorer, preview, sign-in. `workspace_shell.dart` = responsive layout split at `kCompactBreakpoint` (mobile PageView swipe; desktop/tablet rail + resizable split), with a third branch for touch tablets (`_buildTabletTouch`) at any width, where both panes are docked and the context pane starts closed. `widgets/window_title_bar.dart` mounts above the route only for a non-touch desktop at `>= kMediumBreakpoint`, which makes it the ONLY way back from a hidden pane — WorkspaceShell publishes those affordances through `sidebarControlProvider` / `contextPanelControlProvider`, and `new_session_screen.dart` republishes the sidebar half against the same shared `sidebarHidden` setting. **Both panes are hand-rolled and ALWAYS mounted, deliberately not `Scaffold.drawer`/`endDrawer`**: Flutter's `DrawerController` drops its child from the tree while closed, which would dispose `WorkspacePanel`'s `PreviewScreen` WebView and terminal on every close — the same class of regression the `_agentPanelKey`/`_contextPanelKey` GlobalKeys exist to prevent. **Only the sidebar answers to a fling, and only on its own half of the screen**; the context pane opens from `WorkspaceMenuButton`'s popup and closes from its tab bar, because a pane a swipe could also OPEN made every sideways drag over the agent a coin flip. The dispatcher watches RAW pointers, so it fires under a descendant that already won the arena: putting a swipeable widget beside the agent, or giving the context pane a fling again, reintroduces an arbitration problem that currently has no arbiter. The session's breadcrumb/branch/agent-mark/mode/handler cluster belongs to `AgentBar` (`widgets/agent_panel.dart`) and the title bar carries no fallback for any of it — a panel mode that mounts no agent bar (`agentBarMountedProvider`) leaves the whole cluster unreachable until it is restored, rather than relocating any piece into the title bar. The bar's elastic middle carries `SessionSearchField` and is also the window drag target, so nothing may fill it edge to edge. Pane animation and menu-sync mechanics are documented on the members themselves in `workspace_shell.dart`.
- **The session search is a POPUP, not a filter over anything on screen**, and **desktop and mobile are deliberately DIFFERENT surfaces, not one responsive widget** — both decisions, and the reasoning for each, are on `widgets/session_search_field.dart` and `widgets/session_search_modal.dart`; the behaviour is pinned by `test/widgets/session_search_test.dart` and `test/widgets/session_search_modal_test.dart`. What spans files and so lives here is WHICH surface mounts WHERE. A touch tablet is mobile's surface at ANY width, and so is a narrow non-touch desktop window (`< kMediumBreakpoint`), because neither has a title bar to host a field in. `new_session_screen.dart` routes any touch platform through the same branch as phone width (`isMobile || isMobilePlatform`), reserving the search-only variant (`showSearchButton`, no hamburger — the drawer there is a persistent pane) for a narrow non-touch desktop window; inside a session, `WorkspaceShellState._focusSessionSearch` opens the modal for Ctrl/⌘-K under the same condition. Results come from `sessionSearchResultsProvider` over Recent's rows — the one flat view spanning machines and projects — which reads the persisted session cache and NEVER the wire: a keystroke must not dial a machine. Only the shared `SessionSearchResults` is common, so the two surfaces can never answer differently.
- `models/` — Dart mirrors of agent protocol types.
- `demo/` — the offline sample project reachable with no account. `demoModeProvider` is the single switch, in memory only; while it is on `agentTransportForProvider` hands back a `DemoTransport` over canned wire frames, so the demo renders through the real `MessageRouter`, the real per-project services and the real widgets rather than a parallel set of fakes, and `screens/demo_home.dart` replaces `AppShell` as the root route. `demo/fixtures/` are RAW wire envelopes on purpose — a frame `parseAbMessage` rejects is dropped silently and shows up only as an empty surface, which `test/demo/demo_fixture_contract_test.dart` walks every one of them for. **The invariant is that nothing about the demo reaches disk, spawns a bridge host, or phones home, and it is held by scattered call-site gates rather than by a boundary — so anything added later leaks by default.** No test can fail for a gate you never wrote, which is why this stays here and not in a docstring: every new persistence store, host-spawn path, analytics sink and first-run latch has to check `demoModeProvider` (or `isDemoProjectId`/`isDemoEntryId`) for itself. Prefer gating inside the STORE over gating at each caller, and pin the new gate in `test/demo/demo_isolation_test.dart`. The host-spawn class keeps recurring, because a `LocalProject` target is what arms it and the demo's target IS one: every `ensureHost()` caller reachable from the workspace or the New Session canvas needs its own gate, and each swallows its failure, so the value it returns cannot tell a gate from a spawn.
- `design/` — design system (see Design Rules at the bottom of this file).
- **No app-side pairing.** `PairingService`/`PhoneIdentity` and the whole Dart pair surface (`pair_sign`/`pair_verify`/`account_membership_sign`, the `Pair*`/`Grant*` message classes, `RelayService.requestPair`/`grantRevoke`/`unpair`) are deleted — admission is account trust. The relay/bridge/wire TS pair machinery is deleted too; the Dart client still tolerates the old frame types (parses to null, never fatal) in case an un-upgraded relay is still speaking them.
- `recent_agents.dart` — `RecentAgent` rows in `SharedPreferences` (`antgrid.recent_agents.v4`, `dev.`-prefixed in a local dev build per `storage_scope.dart`) are a pure COORDINATES cache — `relayUrl` + the `ed25519Pub` to pin the machine against, public values only, never key material — and drive the reconnect list. Each key bump drops stale rows rather than migrating (pre-release).
- **E2E handshake v2 crypto, v3 session driver** — domain `antgrid.e2e-handshake.v2`; Dart crypto modules in `packages/antgrid_relay_client/lib/src/e2e/` (mirror of `bridge/src/e2e/`, transcript bytes unchanged); spec at `docs/protocol/e2e-handshake.md`. `ConnectionHandshake` (in `antgrid_relay_client`, NOT app-side — the app only injects the `AbLog` sink via `relay_mechanisms.dart`'s `_logHandshake`) drives one attempt: phone-generated `attemptId` correlates every frame (never enters the transcript), kind-byte framing (0x01 handshake plaintext, 0x00 sealed) replaces plaintext-lockout flags, and sealed `app:ready` is retransmitted every 2s until the agent's sealed `established{attemptId}` — no app traffic before it. Rekey (owned by `MachineSession`): 20s receive-silence → sealed ping, 2 missed pongs or repeated RPC timeouts or peer-online-after-offline → fresh handshake on the live socket, swap+zeroize on establishment. Invariants: confirm tags gate establishment; session keys are per-connection, never persisted.
- **App is account-authenticated.** `sign_in_screen.dart` + `auth_service.dart` (Better-Auth session) sign the user in; `post_signin_provisioning.dart` provisions a device (clientId/secret in keychain via `KeychainDeviceStore`); `license_token_minter.dart` mints OAuth `client_credentials` tokens (mirrors `bridge/src/auth/oauth-client.ts`). `account_agents_api.dart` (`GET /account/agents` → `InventoryAgent.ed25519Pub`) and `devices_api.dart` talk to the web account service over TLS. The app connects and signs the E2E transcript as its own `kind:"app"` `DeviceRecord`, which the agent resolves from the account peers inventory — there is no pair-request and no relay grant. A machine's `ed25519Pub` comes from `/account/agents` (a relay-independent anchor) with the `RecentAgent` pin as the offline fallback.
- **One relay slot per machine.** `connectionIdentityFor(record, machineDeviceId:)` scopes the hello's `deviceId` to `relaySlotId(...)` (see `packages/antgrid_relay_client/CLAUDE.md`) so N machines can be open at once; the E2E transcript keeps the BARE `record.deviceUuid`, which is what the agent resolves us by. Because the slots differ, `relayEpochProvider` staying one-per-launch is correct — each slot arbitrates independently.
- **Desktop's remote-control identity is a separate device from its own bridge.** `providers/connection_identity.dart`'s `connectionDeviceRecordProvider` is what a remote-control connection signs the E2E transcript with: mobile reuses the main account `DeviceRecord`, but desktop must dial as a dedicated, lazily-provisioned `kind:"app"` controller record — the desktop's MAIN record is the LOCAL bridge's own relay identity (`kind:"agent"`), and reusing it would epoch-collide with that same bridge. Keep this split intact; it's easy to silently break by wiring a connection to the main record on desktop too.

## Invariants

Rules a change here can break silently. Mechanism lives at the declarations;
these are the ones that span more than one file.

**Lifecycle invariants:** one lifetime authority (`ProjectSessionRegistry`); per-project services (focus switch = rebind, no attach/detach race); welcome-replay safe (subscribe at construction).

**Terminal display is a coordinated app/bridge protocol.** `TerminalService`
consumes independent frames and paged history; unsupported versions require an
upgrade and attachment recovery must never enable raw-stream fallback. Protocol
limits and history boundaries mirror `bridge/src/terminal-frames/protocol.ts`.
Native compatibility runs in `test/terminal_frame_prototype_test.dart` and the
desktop packaging workflow; missing native assets must fail qualification.

**Never read a per-project service façade (`sessionsServiceProvider`, `terminalServiceProvider`, …) outside `build()`.** They THROW while the focused project's `ProjectSession` is unresolved, and a focused project id is no proof one exists: focus is written before any session is built (deep link, `NavController._apply`) and a live session is invalidated under a steady focus (`host_status.dart`, `registry_eviction.dart`, the connection-retry action). From a handler, timer, or post-`await` resumption that throw lands outside any `build()` as an unhandled error — it shipped as a fatal in 1.20664.138. Use `focusedServiceOrNull(container, (s) => s.xService)` there, `serviceWhenReady` in `build()`, and `warmServiceFor(container, entryId, (s) => s.xService)` for an explicit user action — it warms a cold or re-resolving project instead of answering null in the very window the action exists to recover from, and is keyed on an explicit entryId so a dialog outliving its focus can't retarget the action at another agent. `mounted` is not a substitute — it says the widget is alive, not that the session is.

**The invariants below are gated and so live at their declarations**, named here only so you know to look: `TunnelHttpRequest.acceptEncodings` defaults to `[kTunnelGzipEncoding]` and emptying it silently puts every preview back on the uncompressed path (`models/preview_models.dart`, pinned by `test/models/preview_models_test.dart`); the desktop panels keep GlobalKey identity across `_PanelMode` changes or Flutter reconciles by position and UNMOUNTS the panel, disposing the preview's WebView and the agent terminal (`screens/workspace_shell.dart`, pinned by `test/workspace_panel_reparent_test.dart` and `test/widgets/resizable_pane_test.dart`, which also pins that `ResizablePane` must never inflate its panes during layout); and a queued start is not a stopped session — every auto-start and every rendering path must gate on `sessionStartQueued` or it sends a second, promptless start into an unprovisioned workspace (`providers/session_setup.dart`, `models/session_entry.dart`, pinned by `test/providers/session_setup_test.dart` and `test/providers/new_session_queued_start_test.dart`); and `kUnroutedInboundTypes` names the three streamed tunnel frames (`project/project_message_classification.dart`, pinned by `test/project/classification_gate_test.dart`).

**Deep links are `app_links`' alone; the framework must never route one.** The guard itself is documented on `PlatformRouteGuard` (`navigation/platform_route_guard.dart`) and pinned both ways by `test/navigation/platform_route_guard_test.dart`, which asserts the crash without it. **The other half is gated by nothing and lives only here**: `flutter_deeplinking_enabled=false` in the Android manifest and `FlutterDeepLinkingEnabled=false` in the iOS/macOS plists. The embedders' own handling defaults to ON and forwards every VIEW intent, no Dart test reads those files, and only the Android half is mentioned in any source comment — so a platform-config change can restore the fatal with the whole suite green.

**Never carry a `WidgetRef` across an `await` in an activation/action handler.** Drawer and session rows are disposed by the very switch they trigger, and a `WidgetRef` read on a dead element throws (`Bad state: Using "ref" when a widget is about to or has been unmounted`) — it shipped as a fatal in 1.0.6. Capture `ref.container` (Riverpod 3 exposes it on `WidgetRef`) BEFORE the first await and pass that down; the whole activation chain (`activateDrawerEntryById`, `openRemoteProjectForActivation`, `selectProject`, `recordProjectFocus`, `resetNewSessionForm`, `openUpgrade`, …) takes a `ProviderContainer` for this reason. `BuildContext` stays a widget context, but only behind `context.mounted` for UI (snackbars, dialogs, pops).

**Never start async work from a `void` callback without `detached` (`util/detached.dart`).** A tap handler, a post-frame callback and a `ref.listen` all DISCARD the future they start, so a rejection reaches `PlatformDispatcher.onError` as a FATAL with no in-app frames to point at the site — which is how a `session:*` reply dropped while the transport re-establishes (`PendingReply`'s routine 15s `TimeoutException`, already reconciled by the next `session:updated` push) shipped as a crash in 1.20668.151. `await`ing INSIDE such a callback is not a fix — the callback is the boundary, and an `async` closure passed where a `VoidCallback` is expected is the same bug wearing an await. Where the user pressed something and is owed an answer, also catch the `TimeoutException` at the call and say so in the UI; a log line alone makes a confirmed action indistinguishable from a dropped tap.

**`AbConfig` must round-trip every top-level `antgrid.yaml` key it does not model.** `ProjectSettingsScreen`'s Save re-serializes the whole config through `models/ab_config.dart`, so a key the model drops is DELETED from the user's file — `worktree` is carried verbatim as a raw map for exactly that reason, and a new block in `bridge/src/config.ts` with no home here is a data-loss bug nothing type-checks. A write also re-emits the YAML through the bridge's serializer, losing the user's comments and formatting: weigh that before adding another surface that edits the config on the user's behalf.

**A Store update while the bridge host is alive permanently bricks the package.** Every child of the app inherits its Desktop AppX **silo** (measured on 26200 — children do NOT break away), so `antgrid-bridge.exe` and its whole PTY tree are silo members. The update force-kills the app, which fires neither `didRequestAppExit` nor `HostTeardownObserver`; `owner-watchdog.ts` notices ~2s later and then drains *gracefully* for up to 5s more, so members are still live while the Store destages. A silo destroyed with members leaks the package's Helium hives (`%LOCALAPPDATA%\Packages\<family>\SystemAppData\Helium\{User,UserClasses}.dat`) mounted with no owner; the next launch cannot convert a fresh job into that family's silo, fails `ERROR_SHARING_VIOLATION` (0x80070020 → AppXDeploymentServer events 215 + 208), and the shell reports "Another program is currently using this file". **Only sign-out or reboot clears it** — `Reset-AppxPackage`, `Add-AppxPackage -Register`, and service restarts all fail, and Windows' own `RepairAppRegistrationOption` retry is what fails on every launch. The hard backstop is `app/lib/launcher/windows_job_object.dart`: the app assigns each spawned host to a job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and never closes the handle, so the kernel sweeps the tree as it reaps the app — on force-kill too, which is the only path that matters. A nested job inside a silo IS permitted and DOES sweep grandchildren (measured). Keep the assignment BEFORE the stdin bootstrap write in `spawnHostProcess`: the host blocks on `readBootstrapPayload()` as its first act, which is the only thing making the window race-free — and it only holds while the spawned pid IS the bridge, not the `cmd.exe` of a `.cmd` `ANTGRID_AGENT_BIN`. POSIX has no equivalent that survives a SIGKILLed parent — the watchdog stays the sole backstop there — and no tree kill either: the host is spawned `ProcessStartMode.normal`, so it leads no process group and `kill(-pid)` is a guaranteed ESRCH. `terminateTree` (`app/lib/launcher/discovery.dart`) gets its reach on POSIX by SIGTERMing first, which the bridge traps and answers by sweeping its own PTYs with `killProcessTree`, escalating to SIGKILL only after a grace; going straight to SIGKILL there orphans every child that ignores the pty hangup. `UpdateInstallController` (`app/lib/update/update_install_controller.dart`) drains the host gracefully before handing an update to the Store, but that is an improvement on the sweep, never a replacement — the job object stays the only thing standing between a mistake here and a bricked package. The app remains fully interactive for the Store's whole window (two consent dialogs, download, deploy), so the drain alone would be undone by the first `ensureHost()`; `HostController.sealSpawns()` is what makes it hold, and every path that does NOT hand the process over owes an `unsealSpawns()` — a seal nothing lifts leaves the machine unable to start any agent.

## Design Rules (app UI)

Terminal-native system in `app/lib/design/`. **NEVER use raw Material widgets for visual elements.**

- **NEVER** `Icons.*` — use `AbIcons.*` (Codicons via `iconify_flutter`, rendered through `AbIcon`).
- **NEVER** FABs, ripples, elevation/box shadows. Separate with 1px borders (`borderSubtle`, `borderDefault`).
- **NEVER** inline color/spacing literals — use `AbTokens` constants (`spaceN`, palette, radius).
- **Browse `app/lib/design/widgets/` before hand-rolling UI** — an Antgrid widget almost certainly already exists.
- **Fonts: sans for chrome, mono for code/data.** Chrome (labels, headers, buttons, rows, menus, breadcrumbs, dialogs, banners, nav) → `AbTokens.sansStyle()` or the theme default. Code/data (terminal, file content, diffs, paths, git refs, command ids, ports/URLs, kbd chips) → `AbTokens.monoStyle()`. Enforced by `npm run check:font-tokens`.
- **Dialogs** — `dialogTheme` in `ab_theme.dart` owns background/shape/border; don't override inline. Use `AbIconButton(icon: AbIcons.close)` in the title row (not a `TextButton('Close')` action); title uses `AbTokens.monoStyle`.

**Tokens:** zinc grays, indigo accent, tight radii; **JetBrains Mono NL** (bundled) for code/data and the platform system sans for UI. Exact values live in `AbTokens` (`app/lib/design/ab_tokens.dart`) — read them there, never restate them here.

**Layout:** Mobile (< `kCompactBreakpoint`) = two swipeable fullscreen pages (agent left, workspace right). Desktop/tablet (>= `kCompactBreakpoint`) = three-zone: sidebar rail → context panel → agent panel — the window title bar (nav, inline search field, pane toggles) only mounts for a non-touch (mouse) desktop at `>= kMediumBreakpoint`. Below that on a mouse desktop it's a forced-visible sidebar + `_PanelMode`-toggled panel, reusing mobile's icon-button session search. On ANY touch platform (Android/iOS) the title bar never mounts, at any width — both the sidebar (open by default) and the context panel (closed by default) are hand-rolled, always-mounted, docked panes (`WorkspaceShellState._buildTabletTouch`), open/closable by edge swipe or a button in `AgentBar`. A real swipeable `Scaffold.drawer` sidebar survives only at phone width. See the `screens/` bullet above for the full breakdown. Breakpoints in `app/lib/constants/breakpoints.dart`.
