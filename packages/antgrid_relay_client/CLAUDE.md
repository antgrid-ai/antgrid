# `antgrid_relay_client` (the app's relay layer)

Pure Dart relay/crypto client, no Flutter. Deep reference for this package;
the consuming app is documented in `app/CLAUDE.md`, and the E2E handshake
invariants (shared with `bridge/src/e2e/`) are written up there under
"E2E handshake v2 crypto, v3 session driver".

- `relay_slot.dart`: the app's `hello.deviceId` is a per-machine SLOT, `<accountDeviceUuid>#<machineDeviceUuid>` (`relaySlotId`). The relay arbitrates per `hello.deviceId` and supersedes an equal epoch, so one slot shared across machines lets the second machine dialled kill the first. A slot is a TRANSPORT address only — the E2E transcript, every bridge-side identity lookup and the relay's revoke-by-account-device use `baseSlotDeviceId`. Hand-mirrored by `packages/antgrid-wire/src/relay-slot.ts` (the single TS copy, imported by bridge AND relay); keep in lockstep (a divergence is an admission failure, not a type error). The separator must also be legal in `antgrid-wire`'s `DEVICE_ID` regex, which gates `hello.deviceId` and a route header's `to` — a schema miss is `PROTOCOL_VIOLATION` before the signature is checked.
- `relay_service.dart`: v3 signed `hello` (mandatory `licenseToken` + `epoch`; deviceId = the slot above), `welcome` = authenticated. ONE attempt per `connect`, never a retry — redial timing, backoff and give-up belong to `app/lib/connection/`'s `ConnectionSupervisor`, so there is exactly one component in the app deciding when to try again. Typed `errorStream` (required `retryable`/`ref`) is the SOLE failure channel — license verdicts are not a side channel, `ConnectionSupervisor.noteRelayError` classifies `LICENSE_EXPIRED|REVOKED|INVALID`/`SUPERSEDED` off its `code` directly into `Blocked(reason)`; `retryable:false` before close → no reconnect; `SUPERSEDED` is terminal-for-socket but NOT a license error. Clock-skew: `error{AUTH_FAILED, serverTime}` → `ts` offset on next hello, once per offset.
- `machine_session.dart`: `MachineSession` = one E2E session per machine (handshake/rekey driver, liveness ping/pong, frag reassembly) demuxing `{s, m}` envelopes to per-project `StreamTransport`s (`s` absent/`"0"` = control plane); sealed session frames (`agent-ready`, `app:ready`, `established`, `ping`, `pong`) are BARE `{type}` objects, never enveloped. A `stream-invalid {streamId}` from the agent (host restart — the id died with the old process) marks the binding dead so every reader treats the project as unbound, and re-drives `project:start` via the injected `projectStartMessageBuilder`; the binding itself stays in `_projectStreamIds` because `_recordProjectStream` needs it as `prev` to re-point the live `StreamTransport` onto the new id. An `agent:projects` advert that DROPS a bound project's streamId (restart re-opened it locally → dialable:false, so there is no replacement id to migrate onto) takes the same path when a live transport still holds the dead id — forgetting the binding alone strands every service on it. `RelayConnectionState` has no pairing rung — `authenticated` is terminal for the socket, and agent presence is a separate signal (`peerPresenceStream`). The current relay never emits pairing frames (`pair-connected`/`grant-revoked`/`pair-*` — the ceremony they belonged to is gone). `parseRelayMessage` falls through any unrecognized `type` to null rather than throwing, which is correct hygiene for any unknown/retired frame regardless of what the current relay speaks — an older relay binary a client might still be pointed at is exactly the case this tolerance exists for. `AppState.copyWith` deliberately auto-clears `errorCode`/`error` — see its doc comment before "cleaning up".
- `connection_handshake.dart`: `ConnectionHandshake` (one v3 attempt: `attemptId`, kind-1 client-hello, sealed `app:ready` retransmitted until the agent's sealed `established`) and `AppSessionHandshaker`, the `SessionHandshaker` a `MachineSession` drives. "App" is the ROLE — every phone-side client is the initiating half. It lives HERE, not in `app/`, so the Flutter app and the `antgrid_eval_client` CLI drive the same driver: the app-side copy is what let the eval client sit on the v2 conversation through a whole protocol revision while its scenarios stayed skipped. Keep it Flutter-free — diagnostics go through the injected `HandshakeLogger` (the app wires it to `AbLog`), never a direct logger import.
- `lib/src/e2e/` — Dart mirror of `bridge/src/e2e/`; transcript bytes must stay byte-identical. Spec: `docs/protocol/e2e-handshake.md`. The TRANSPORT cipher alone is swappable: `E2eTransportDart.useAlgorithm` takes any `AesGcm` (the app installs a native-backed one — see `app/lib/config/native_crypto.dart`; the default pure-Dart cipher runs at single-digit MB/s on the calling isolate, and a tunneled preview response is megabytes of it). Anything installed there MUST stay byte-compatible with node:crypto's `aes-256-gcm` and the `nonce(12) || ciphertext || tag(16)` framing — `test/e2e_transport_algorithm_test.dart` pins that both ways. The handshake primitives are deliberately NOT swappable: they produce the transcript bytes the bridge verifies.
- `frag.dart` — the reassembly budget charges each part via `utf8ByteLength`, NOT `utf8.encode(data).length`: the latter allocates a full copy of a multi-MB fragment to produce a number, once per fragment on the UI isolate. It must keep agreeing with the encoder (including U+FFFD for an unpaired surrogate) so a transfer costs the same here as it does against the bridge's `Buffer.byteLength` — `test/frag_test.dart` pins that.
- The Dart client mirrors the `antgrid-wire` Zod schemas **by hand** — keep it in lockstep when wire schemas change. Enforced by the shared control-envelope vectors (`evals/fixtures/relay-envelope-vectors.json`): regenerate via `packages/antgrid-wire/scripts/gen-envelope-vectors.ts`, then both `packages/antgrid-wire/tests/relay-envelope-vectors.test.ts` (union/ErrorCode completeness) and `test/relay_envelope_vectors_test.dart` (mirror parses/emits every vector) must pass.
