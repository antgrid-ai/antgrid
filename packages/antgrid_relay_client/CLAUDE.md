# `antgrid_relay_client` (the app's relay layer)

Pure Dart relay/crypto client, no Flutter. Deep reference for this package;
the consuming app is documented in `app/CLAUDE.md`, and the peer session
invariants (shared with the bridge) are written up there under "Session hello,
no app-layer crypto", with the full protocol spec at
`docs/protocol/peer-session.md`.

What may be written in any `CLAUDE.md`, this one included, is governed by
*Maintaining these files* in the root `CLAUDE.md`.

- `relay_slot.dart`: the app's `hello.deviceId` is a per-machine SLOT, `<accountDeviceUuid>#<machineDeviceUuid>` (`relaySlotId`). The relay arbitrates per `hello.deviceId` and supersedes an equal epoch, so one slot shared across machines lets the second machine dialled kill the first. A slot is a CENTRAL transport address only: every bridge-side identity lookup and relay revocation use `baseSlotDeviceId`; peer frames carry no address because an authenticated native connection already identifies its peer. Hand-mirrored by `packages/antgrid-wire/src/relay-slot.ts`; keep the two implementations in lockstep. The separator must remain legal in `antgrid-wire`'s `DEVICE_ID` regex, which gates `hello.deviceId` before the signature is checked.
- `relay_service.dart`: v3 signed `hello` (mandatory `licenseToken` + `epoch`; deviceId = the slot above), `welcome` = authenticated. It is control-only: authentication, account-scoped presence, policy changes, heartbeat, and push control stay central; payloads never traverse this socket. ONE attempt per `connect`, never a retry - redial timing, backoff and conflict handling belong to the app's connection supervisor. Typed `errorStream` (required `retryable`) is the sole control failure channel. Clock-skew correction remains `error{AUTH_FAILED, serverTime}` -> `ts` offset on the next hello, once per offset.
- `peer_link.dart`: the native payload boundary is Flutter-free. `MachineSession` and the session-hello driver consume it; `RelayService` does not implement it. Native links must never derive payload close/restart from central presence or authentication changes. Lease implementations must clear `isDispatchAllowed` synchronously before emitting lifecycle events; `MachineSession` rechecks it immediately before every send.
- `machine_session.dart`: `MachineSession` = one session per machine (hello driver, wedge-probe ping). A project stream's own RPCs are tracked per stream: 3 consecutive timeouts reset and reopen that stream alone (`kProjectStreamTimeoutsToReset`), never the link, and its durable-state pull is a single `state.snapshot` request under one deadline (`kSnapshotPullDeadline`). A project's traffic never shares the session's socket: each project gets its own native QUIC stream (`MachineSession.openProject`), with bare `AbMessage` JSON records, and the session stream carries only the control plane. Every record on the session stream is a bare length-prefixed JSON body with no envelope; the JSON `type` alone tells a session frame from a control-plane one, via `isSessionFrameType`/`kSessionFrameTypes` — not a `ping`/`pong` literal, since those are ordinary `AbMessage` types too (only the `session:`-prefixed names are session frames). Plaintext session frames (`session:hello`, `session:established`, `session:ping`, `session:pong`, `session:takeover`) stay BARE objects keyed by `type` on that control-plane socket. Opening a project stream requires the agent to have advertised it ready first (hazard J: `stream-ready {projectId}` or an `agent:projects` entry with `running:true`, tracked in `_readyProjects`) — an open attempted before that is refused `NOT_READY` in-band (`StreamRefused` record + FIN, retried once, then failed) rather than parked, since Dart cannot read a QUIC reset code. A project stream that ends while still wanted reopens on its own with growing backoff (`kProjectStreamReopenInitialBackoff`..`kProjectStreamReopenMaxBackoff`); every live one reopens AT ONCE with no backoff at each fresh session establishment. A stream's identity IS its project (`StreamTransport.projectId`, fixed for its lifetime), so there is no id to migrate after a restart. Per-peer caps (`kStreamMaxProjectsPerPeer` etc., `models/stream_open.dart`) are checked synchronously before any wait, so an over-cap open fails `CAP_EXCEEDED` at once and never calls `openStream`. A disposed project transport still holds its cap slot until its stream's records actually drain (mirrors the terminal-attachment carry-over — the bridge counts a stream until it sees the end), so a racing reopen cannot draw a spurious `CAP_EXCEEDED`. Keep this in lockstep with `bridge/src/project-streams.ts`: no suite spans both halves. `RelayConnectionState` describes the central control socket only; agent presence is separate discovery information on `peerPresenceStream`. `parseRelayMessage` falls through any unrecognized `type` to null rather than throwing, preserving forward compatibility. `AppState.copyWith` deliberately auto-clears `errorCode`/`error` — see its doc comment before "cleaning up". QUIC flow control is the only backpressure: `sendOnSession` writes straight to the link, serialized on one `_sessionSendChain` so a dequeue-time check against the session generation (the `_SessionGeneration` fence, `app/CLAUDE.md`'s "Session hello, no app-layer crypto") drops a frame still queued when its session goes down rather than handing it to a successor session. Its future means "handed to the link, or dropped", never "a peer got it", so an app-side caller that cannot wait out the traffic ahead of it must impose its own timeout. A project transport's `send` writes straight to its own native stream, serialized per-transport by its own send chain. Session frames (`session:ping`, `session:pong`) are written directly and unchained.
- `connection_handshake.dart`: `ConnectionHandshake` (one plaintext attempt: a fresh `attemptId`, `session:hello` sent once, no retransmit, resolved by the bridge's `established`) and `AppSessionHandshaker`, the `SessionHandshaker` a `MachineSession` drives. `kSessionHelloCapabilities` here is the app's half of the hand-mirror with `SessionHelloCapabilities` (`bridge/src/protocol.ts`) — see the capabilities rule in root `CLAUDE.md`. "App" is the ROLE — every phone-side client is the initiating half. It lives HERE, not in `app/`, so the Flutter app and the `antgrid_eval_client` CLI drive the same driver: the app-side copy is what let the eval client sit on a stale protocol conversation through a whole protocol revision while its scenarios stayed skipped. Keep it Flutter-free — diagnostics go through the injected `HandshakeLogger` (the app wires it to `AbLog`), never a direct logger import.
- `upload_stream.dart`: one file upload's handles, transport-agnostic — the native path via `StreamTransport.openUpload`'s own native QUIC stream, or the loopback path via `LocalTransport`'s `file:upload-local`, mirroring `terminal_attachment.dart`'s split.
- The Dart client mirrors the `antgrid-wire` Zod schemas **by hand** — keep it in lockstep when wire schemas change. Shared fixtures enforce both boundaries: `relay-envelope-vectors.json` pins central control envelopes and `peer-transport-vectors.json` pins peer-frame bytes plus transport limits. Regenerate them with the scripts in `packages/antgrid-wire/scripts/`; TypeScript and Dart vector tests must both pass.
