# `antgrid_relay_client` (the app's relay layer)

Pure Dart relay/crypto client, no Flutter. Deep reference for this package;
the consuming app is documented in `app/CLAUDE.md`, and the peer session
invariants (shared with the bridge) are written up there under "Session hello,
no app-layer crypto", with the full protocol spec at
`docs/protocol/peer-session.md`.

What may be written in any `CLAUDE.md`, this one included, is governed by
*Maintaining these files* in the root `CLAUDE.md`.

- `relay_slot.dart`: the app's `hello.deviceId` is a per-machine SLOT, `<accountDeviceUuid>#<machineDeviceUuid>` (`relaySlotId`). The relay arbitrates per `hello.deviceId` and supersedes an equal epoch, so one slot shared across machines lets the second machine dialled kill the first. A slot is a CENTRAL transport address only: every bridge-side identity lookup and relay revocation use `baseSlotDeviceId`; peer frames carry no address because an authenticated native connection already identifies its peer. Hand-mirrored by `packages/antgrid-wire/src/relay-slot.ts`; keep the two implementations in lockstep. The separator must remain legal in `antgrid-wire`'s `DEVICE_ID` regex, which gates `hello.deviceId` before the signature is checked.
- `relay_service.dart`: v3 signed `hello` (mandatory `licenseToken` + `epoch`; deviceId = the slot above), `welcome` = authenticated. It is control-only: authentication, account-scoped presence, policy changes, heartbeat, and push control stay central; payloads never traverse this socket. ONE attempt per `connect`, never a retry - redial timing, backoff and conflict handling belong to the app's connection supervisor. Typed `errorStream` (required `retryable`) is the sole control failure channel. Clock-skew correction remains `error{AUTH_FAILED, serverTime}` -> `ts` offset on the next hello, once per offset.
- `peer_link.dart`: the native payload boundary is Flutter-free. `MachineSession` and the session-hello driver consume it; `RelayService` does not implement it. Native links must never derive payload close/restart from central presence or authentication changes. Lease implementations must clear `isDispatchAllowed` synchronously before emitting lifecycle events; `MachineSession` rechecks it immediately before every send.
- `machine_session.dart`: `MachineSession` = one session per machine (hello driver, liveness ping/pong, frag reassembly) demuxing `{s, m}` envelopes to per-project `StreamTransport`s (`s` absent/`"0"` = control plane); plaintext session frames (`session:hello`, `established`, `ping`, `pong`, `credit`) are BARE objects keyed by `type`, never enveloped. A `stream-invalid {streamId}` from the agent (host restart — the id died with the old process) marks the binding dead so every reader treats the project as unbound, and re-drives `project:start` via the injected `projectStartMessageBuilder`; the binding itself stays in `_projectStreamIds` because `_recordProjectStream` needs it as `prev` to re-point the live `StreamTransport` onto the new id. An `agent:projects` advert that DROPS a bound project's streamId (restart re-opened it locally → dialable:false, so there is no replacement id to migrate onto) takes the same path when a live transport still holds the dead id — forgetting the binding alone strands every service on it. The OPPOSITE direction — a frame arriving on a streamId this session holds no transport for — is dropped and answered with `stream-unbound {streamId}` on the control plane, rate-limited per id; the agent mutes that stream until we transmit on it or it re-announces `stream-ready`. Keep the pair symmetric with `bridge/src/stream-mux.ts`: no suite spans both halves, and the fail direction is silent and unbounded — the agent streams a project from the moment its transport is up, this side builds the receiving transport only when the user opens that project, and nothing bounds the gap. `RelayConnectionState` describes the central control socket only; agent presence is separate discovery information on `peerPresenceStream`. `parseRelayMessage` falls through any unrecognized `type` to null rather than throwing, preserving forward compatibility. `AppState.copyWith` deliberately auto-clears `errorCode`/`error` — see its doc comment before "cleaning up". Outbound APP frames go through `send_scheduler.dart`: one drain loop for the whole session, checked against the session generation at DEQUEUE (so a frame still queued when its session goes down is dropped and logged, never written to a successor session — see the `_SessionGeneration` fence in `app/CLAUDE.md`'s "Session hello, no app-layer crypto"), control before preview, FIFO within a channel — and `sendOnStream`'s future therefore means "handed to the socket, or dropped", never "a peer got it", so an app-side caller that cannot wait out the traffic ahead of it must impose its own timeout. Session frames are written directly and bypass the GATE, not the accounting: they are charged against the channel window like any other frame but never held by it, which is what keeps liveness and credits running while a channel cannot drain. Per-channel credit windows and the cumulative `credit` frame that opens them are specified in `docs/protocol/peer-session.md` §5; the constants are hand-mirrored from `packages/antgrid-wire/src/flow.ts` in `lib/src/flow.dart`.
- `connection_handshake.dart`: `ConnectionHandshake` (one plaintext attempt: a fresh `attemptId`, `session:hello` sent once, no retransmit, resolved by the bridge's `established`) and `AppSessionHandshaker`, the `SessionHandshaker` a `MachineSession` drives. `kSessionHelloCapabilities` here is the app's half of the hand-mirror with `SessionHelloCapabilities` (`bridge/src/protocol.ts`) — see the capabilities rule in root `CLAUDE.md`. "App" is the ROLE — every phone-side client is the initiating half. It lives HERE, not in `app/`, so the Flutter app and the `antgrid_eval_client` CLI drive the same driver: the app-side copy is what let the eval client sit on a stale protocol conversation through a whole protocol revision while its scenarios stayed skipped. Keep it Flutter-free — diagnostics go through the injected `HandshakeLogger` (the app wires it to `AbLog`), never a direct logger import.
- `frag.dart` — the reassembly budget charges each part via `utf8ByteLength`, NOT `utf8.encode(data).length`: the latter allocates a full copy of a multi-MB fragment to produce a number, once per fragment on the UI isolate. It must keep agreeing with the encoder (including U+FFFD for an unpaired surrogate) so a transfer costs the same here as it does against the bridge's `Buffer.byteLength` — `test/frag_test.dart` pins that.
- The Dart client mirrors the `antgrid-wire` Zod schemas **by hand** — keep it in lockstep when wire schemas change. Shared fixtures enforce both boundaries: `relay-envelope-vectors.json` pins central control envelopes and `peer-transport-vectors.json` pins peer-frame bytes plus transport limits. Regenerate them with the scripts in `packages/antgrid-wire/scripts/`; TypeScript and Dart vector tests must both pass.
