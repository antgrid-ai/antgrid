# Deviations from Carbon web

Every place this package behaves differently from Carbon web (Carbon v11, React
implementation), with the reason and the evidence that supports it. Ids are
referenced from `coverage.md`. Add an entry in the same change that introduces
a deviation, and remove it when the difference goes away.

Evidence names a test file (and test where useful) or, where nothing asserts
the behaviour, the source file.

## Foundations and shared behaviour

| Id | Carbon web behaviour | Flutter behaviour | Reason | Evidence |
| --- | --- | --- | --- | --- |
| F-density | Control sizes 24, 32, 40, 48 px chosen per component (`sm`, `md`, `lg`); no touch-specific mode | Two explicit densities: compact 32 px, touch `touchTarget` (48 px by default, host-settable); small variant is 24 px compact and 48 px touch; icon buttons 32 / 48 px targets | Finger targets need at least 48 px on every native target; density is a host choice, not a viewport guess | `test/foundations/theme_data_test.dart` (density metrics) |
| F-icons | SVG files or components per icon | Glyphs converted to path data in `icons.g.dart` and painted by `CarbonIcon` | Synchronous paint, single-colour tinting, identical rendering in tests, no asset lookups | `test/foundations/icon_test.dart`; `NOTICE` |
| F-focus-ring | CSS `outline` around the element, which may extend outside it | 2 px ring painted inside the bounds as a foreground decoration, with an optional 1 px inner ring on filled controls | No layout shift and no clipping by scroll views and panes; Carbon already uses an inset ring for most controls | `test/primitives/interaction_test.dart` |
| F-touch-type | Productive and expressive sets; no touch-specific set | Control and body text 16 px, label and helper 14 px in touch density, same hierarchy | Readable finger-use text without shrinking to fit fixed boxes | `test/foundations/theme_data_test.dart` (typography follows density) |
| F-popups | Absolutely positioned DOM nodes with their own stacking | `OverlayPortal` anchored popups that flip above or below, clamp to viewport, safe area and keyboard, and dismiss on outside tap, Escape, system back, anchor scroll-out and anchor unmount; start and end alignment only | Inherits theme and layer from the anchor and avoids Navigator routes for transient UI | `test/primitives/popup_test.dart` |
| F-contrast | Gray 90 and Gray 100 secondary, helper and error text on layer 03 and field 03 is below 4.5:1 | Kept as Carbon defines it; excluded from the default contrast pair list and available in `CarbonContrast.extendedPairs` | Changing Carbon's palette values would break role fidelity; custom themes may opt into the stricter set | `test/foundations/contrast_test.dart` |
| F-fonts | Fonts loaded by the page | Families resolve as `packages/carbon_flutter/IBM Plex Sans` and `.../IBM Plex Mono` | Fonts ship inside the package with no network request | `test/foundations/theme_data_test.dart` (typography families) |
| F-routes | Portals inherit CSS from the document | `CarbonScopeRelay` carries the theme into Navigator routes. Theme and density stay live; localizations and text direction are captured when the route opens | Routes mount above the trigger's subtree, so nothing is inherited; the relay currently follows only the theme scope | `test/foundations/theme_widget_test.dart` ('carries localizations and direction captured at open') |
| S-roles | ARIA roles `group`, `searchbox`, `listbox`/`option`, `list`/`listitem` | The Flutter version this package targets has no `group`, `searchBox` or `listBox` semantics role, and its `list`/`listItem` roles must be direct parent and child. A checkbox group is a labelled container with explicit child nodes; search has no search-box role; option rows are buttons with a selected flag in a mutually exclusive group, with the keyboard highlight exposed as the focused flag; contained lists use plain semantics with a header node | Use only roles the framework provides and accepts inside scrolling lists | `checkbox_test.dart`, `select_regressions_test.dart` ('the keyboard highlight is exposed as a focused row'), `contained_list_test.dart` |

## Components

| Id | Carbon web behaviour | Flutter behaviour | Reason | Evidence |
| --- | --- | --- | --- | --- |
| C01-size | Default button size `lg` (48 px) | Height is the density control height (32 compact, 48 touch) unless `size` is given; touch never goes below 48. Sizes small 32, medium 40, large 48, extra large 64; no 2xl (80) | Density sets the default; touch targets stay at least 48 | `button_test.dart` (sizing) |
| C01-padding | 16 px start padding and about 64 px end padding reserved for the icon; labels truncate | Symmetric 16 px horizontal padding, 16 px gap before the trailing icon, 6 px vertical padding; a button that sizes itself (not `expand`, not icon-only, not given a width by its parent) is capped at 320 px wide and a longer label wraps at the cap. In compact density a text button taller than 48 px (extra large, 64) pins its label 14 px from the top, as Carbon's capped block padding does; touch density and icon-only buttons stay centred | A fixed icon slot fights text scaling and RTL; vertical padding lets enlarged text grow the button | `button_test.dart` (200% text) |
| C01-busy | No busy state on Button; pending work is shown with Inline loading beside it | `busy` swaps the icon for a spinner (or overlays a text-only label), keeps size, colours and focus, swallows activation and announces Loading | The requirements need a busy action that cannot submit twice | `button_test.dart` (busy) |
| C01-set-stack | `ButtonSet` stacks only when the page sets `stacked`, in source order (first child on top) | `CarbonButtonSet` stacks automatically when the buttons do not fit side by side, with the last child (the primary action) on top and each button full width. In an end-aligned row each button is a 196 px column (Carbon: `inline-size` 100%, at most 196), or wider when its label needs it, so the set stacks sooner than Carbon's fluid auto-stack, which needs 176 px per button. Keyboard traversal follows the on-screen order (not separately tested) | Labels never clip in narrow containers or at large text | `button_test.dart` ('stacks with the last button on top when narrow'), `button_set_intrinsics_test.dart` |
| C02-textarea | Separate `TextArea` component, 4 rows by default | `CarbonTextInputVariant.multiline` of `CarbonTextInput`; minimum 3 lines, clamped to `maxLines` when the host sets fewer | One widget keeps controller, focus and semantics handling shared | `text_input_test.dart`, `text_input_editing_test.dart` ('multiline maxLines below the default minimum is accepted') |
| C02-counter | Character counter on the label row at the top end | Counter inside the field box: trailing for single-line, bottom end for multiline | `CarbonFieldFrame` owns the label row and has no trailing slot | `lib/src/components/text_input.dart` |
| C02-password-hover | Password toggle hovers with `background-hover` | The toggle hovers with `layer-hover`; its not-allowed cursor when disabled is not drawn | Not yet matched | `lib/src/components/text_input.dart` |
| C02-actions | Clear and reveal buttons inside the field; hover fills the full field height | Actions are overlaid at the field's full height with a 32 / 48 target, so the field does not grow. The hover fill is inset by the focus width (1 px at the bottom when unfocused) so the focus and error outlines (a warning draws none) and the bottom rule stay visible | Targets must meet the density minimum without changing field height; the overlay sits above the box's outline painter | `text_input_editing_test.dart` ('hover fill on an action leaves the focus outline uncovered') |
| C03-focus | Form and FormGroup are layout only | `CarbonFormController.focusFirstInvalid` moves focus to the first field showing an error, in visual order, scrolling it into view; no error summary. When that field already has focus, moving focus would announce nothing, so its label and error are announced instead. Text input and search register themselves; other fields opt in with `CarbonFormFieldRegistrar` | The requirements ask for errors to be discoverable; focusing the field makes the screen reader read its label and error | `form_test.dart` |
| C04-size | Search sizes `sm`, `md`, `lg` | Shares `CarbonFieldSize` with text input and clamps to the density minimum target | Touch must not go below 48 | `search_test.dart` |
| C04-escape | Escape clears the input | With text, Escape clears it, keeps focus and is consumed. With an empty field Escape is not consumed, so an enclosing popup, menu or modal handles it. During IME composition it is left to the IME, and with the selection toolbar open the first Escape closes the toolbar | Escape must not discard unrelated input or swallow a dismissal meant for a container | `search_test.dart`, `text_input_editing_test.dart` ('Escape closes an open selection toolbar before clearing') |
| C04-status | No busy, error or result-count presentation | `busy` swaps the icon for a spinner and announces Loading once; `resultCount` is a polite live region; `errorText` replaces it. The host fetches and debounces | The requirements ask Search to present host-provided status | `search_test.dart` |
| C05-render | Native `<select>` element | A Flutter-rendered field with a listbox popup; read-only stays focusable and never opens; choosing the committed value again reports nothing | Rendering is Flutter-owned per the requirements | `select_test.dart` |
| C05-list | List box with `0 2px 6px` shadow, `text-secondary` options, 1 px rules between options, `layer-selected` when pressed | Shadow, secondary text at rest, dividers and `layer-selected` when pressed as in Carbon; the list uses the field's layer, and is capped at 5.5 rows | Rows share one fixed extent so the highlighted row can be revealed by arithmetic | `select_regressions_test.dart` ('resting options use the secondary text color') |
| C05-truncation | Long items wrap or get a tooltip | Single-line rows with an ellipsis and one shared extent that grows with text scale; the full label is in semantics only, with no tooltip | Uniform rows allow lazy construction and exact scroll reveal; `CarbonTooltip`'s Escape handling would conflict with list dismissal | `select_test.dart` |
| C06-status | Loading and error shown with the list | Loading and error rows are drawn first, above the options | A status row after more than five options would never be built or announced in a lazy list | `select_regressions_test.dart` ('a long list still shows its error row') |
| C06-combo | Combo box has a clickable chevron and a clear button that resets the selection | The whole field toggles the list when tapped outside the text area; the chevron is decorative; expand and collapse semantics actions open and close the list; no clear button. A second Escape discards typed text and restores the committed label | The field's inner height cannot host a 32 / 48 target; a clear button would commit null, while search must never commit | `dropdown_test.dart`, `dropdown_regressions_test.dart` ('the expand action opens the list') |
| C07-target | Native checkbox with a `<label>` | Indicator and label are one target at least the minimum target tall, so a label tap toggles once; the target is the control row, not blank width beside it; the indicator is centred on the label's first line | Shared target size without duplicate toggles | `checkbox_test.dart` |
| C07-indeterminate | Indeterminate bar sits 1 px below centre (SCSS arithmetic) | The bar is centred in the box | Not yet matched | `lib/src/components/checkbox.dart` |
| C07-enter | Native checkbox toggles on Space only | Space, Enter and numpad Enter toggle, and the key is consumed, so an ancestor Enter-to-submit shortcut does not fire while a checkbox has focus | The shared `CarbonInteraction` key map activates on all three; it has no per-instance key map yet | `test/primitives/interaction_test.dart` ('Enter, NumpadEnter and Space activate when focused') |
| C08-readonly | Read-only toggle shows no check mark | A read-only toggle that is on shows a check mark in the handle at both sizes | The read-only track is uncoloured, so the mark gives the on state a cue beyond handle position | `lib/src/components/toggle.dart` |
| C08-busy | No busy state | `busy` shows a spinner in the handle, blocks activation, keeps focus and announces Loading | The host owns persistence; a pending save must not look applied | `toggle_test.dart` (busy) |
| C09-weight | Selected tab label is semibold | One font weight for all tabs; selection is shown by the indicator, primary text colour and the contained fill | A weight change shifts tab widths on selection | `tabs_test.dart` |
| C09-size | Line tabs 40 px; contained tabs `lg` 48 px | 40 compact and 48 touch for both variants | The density table wins over Carbon web | `tabs_test.dart` (sizing) |
