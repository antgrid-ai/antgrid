# Bridge transport migration handoff

## Implemented

- `bridge/src/peer-session-owner.ts` now owns application E2E, transcript/signature verification, confirmation, make-before-break rekey, per-peer fragmentation, queues, credits, project mux and peer liveness. It has injectable logging, routed payload ingress and carrier sinks. `RelayClient` retains central WebSocket authentication, presence, JSON control messages, heartbeat, reconnect and the unchanged public service API.
- `bridge/src/peer/iroh-relay-client.ts` integrates the pinned upstream native endpoint into the real HostServer. One app-initiated connection carries every project for that app/machine pair. Native identity is matched against the authoritative endpoint registration, then existing signed application E2E runs over one reliable bidirectional stream. Additional application streams and invalid route destinations are rejected. Remote dispatch retains the `relay` source, so neither LocalListener nor loopback authorization is involved.
- HostServer allocates project stream IDs. Local dispatch readiness and central registration acknowledgements are separate. Native E2E establishment admits locally ready projects, including projects attached before native establishment; WebSocket sends still require their central registration. Central presence and socket reconnect do not retire a healthy native peer. Native/WS selection is sticky once E2E starts; an unconfirmed late native carrier can be retired for the selected WebSocket hello.
- `peer/authorization-lease.ts` implements single-flight refresh, monotonic request-start expiry, decimal policy highwater fencing, identity binding, stale-response rejection and synchronous invalidation. Upgraded WebSocket sessions use the same lease as native sessions. Every new handshake refreshes authorization, and active remote peers refresh every 20 seconds. Dispatch and dequeue recheck authorization. Native endpoint rotation and peer key/generation changes retire affected E2E sessions.
- `peer/enrollment.ts` derives the endpoint identity from the separate secure bootstrap seed, signs the shared challenge bytes with both device and endpoint keys, verifies all challenge/response bindings and uses historical `registrationGeneration` for rotation. Endpoint secrets stay in the app's protected DeviceRecord and the bridge's process memory, never an ordinary bridge file. Bootstrap `userId` and `endpointSecret` are validated and forwarded by `auth/credentials.ts` and `index.ts`.
- `peer/records.ts` validates length before allocation, uses the shared route-record bound, serializes bounded writes, expires a stalled native write after five seconds, cancels queued records synchronously and fences retired E2E generations. The scheduler now supports asynchronous sinks: outcomes settle after the native write, and control is selected before the next preview frame. Existing synchronous WebSocket behavior is retained.
- Native admission futures have a five-second selection deadline. The binding has no per-Connecting cancellation; a timed-out future retains one bounded admission slot until it settles, then its late connection closes. A timeout never closes the shared endpoint. Native connection close codes distinguish generic connection loss (`1`), protocol violation (`2`) and authorization refusal/revocation (`3`). Upstream string-only error reporting still requires conservative handling by the receiver.
- Native endpoints use the minimal upstream preset plus only backend-approved custom relays. A changed relay map closes affected native peers, closes the old endpoint and rebuilds it under the new map. A native availability/configuration failure leaves a valid leased WebSocket fallback available; authoritative denial does not.

## Selection and packaging

`ANTGRID_PEER_TRANSPORT` selects `websocket` (default), `iroh-preferred`, or `iroh-only`. The latter also requires `ANTGRID_TEST_MODE=1`. The upgraded host requires secure endpoint fields and uses the leased client even in WebSocket mode; missing bootstrap enrollment fails closed and cannot select ordinary RelayClient. An older remote app without endpoint enrollment may still use WebSocket when this host's authoritative peer lease permits its device key. Native binding is `@number0/iroh` exactly `1.1.0`; parent owns the root dependency install and lockfile.

`bridge/CLAUDE.md` records the new owner and the protected bootstrap mirror. Application service interfaces and encryption/command authorization remain in their existing components.

## Remaining qualification and release blockers

- The upstream-only relay service now has raw-I/O fence tests and a trusted-TLS packet/admission/disconnect gate; see `docs/iroh-relay-upstream-audit.md` for subsequent results and remaining binding compatibility qualification. WebSocket remains the default.
- A separate combined real HTTP backend/native host gate passed device-bound enrollment, two project reads during central loss and revocation on the next authoritative refresh. The source/compiled feature smoke remains fixture-authorized; neither result qualifies WAN or physical platforms.
- A revoked endpoint cannot reuse its historical endpoint ID. The enrollment API correctly refuses that attempt; a new protected endpoint seed or explicit re-enrollment is required. Do not weaken backend history uniqueness to recover an old seed.
- Desktop resume has an owner-bearer authenticated loopback `POST /peer-resume` path (no body; 202 `{ok:true}`). It synchronously invalidates leases, closes sessions/queues and fences pending native admission, then serializes a new authoritative request after any pre-resume request settles. App lifecycle notification is owned by the Dart integration assignment. Physical sleep/wake qualification remains outstanding.
- WAN/direct versus forced-relay, blocked UDP, multiple relay home selection/discovery, multiple machines/apps, repeated reconnect, physical mobile packaging and the specified performance workload gates remain unqualified here. Native metrics/latency instrumentation still needs the full release acceptance coverage.
- Native binding error/close metadata is string-only in places. Unknown errors must not be converted into permissive fallback; supported upstream structured classification or conservative terminal behavior is required.
